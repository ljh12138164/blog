# 个人技术手账 UI 设计

## 目标

把现有偏“米白纸张、中文衬线、陶土橙、报刊分栏”的通用编辑风格，重构为简洁、直接且具有作者辨识度的个人技术博客。设计参考 AstroPaper 的窄栏阅读结构与低装饰密度，但不复刻其品牌；本站以“现场注记”作为专属视觉语言，并完整支持明暗模式。

主要读者是正在查找工程问题、技术方案和实践记录的中文开发者。页面的首要任务是让读者快速判断文章是否值得阅读，并舒适地完成长文阅读。

## 已选方向

采用方案 C：AstroPaper × 现场注记。

- 继承窄内容列、纯文字列表、无卡片和清晰排版层级。
- 以无衬线字体承担导航、标题与正文，去除当前模板化的报刊气质。
- 用 `NOTE / 017`、短批注、修订状态和关联问题表达“个人技术手账”。
- 现场注记必须传递真实信息，不能成为随机装饰。
- 不使用纸张纹理、渐变、发光、大面积手写字体、卡片网格或装饰动画。

## 界面范围

### 全站页头与页脚

- 目的：建立站点身份并提供文章、关于、搜索和主题切换入口。
- 主要动作：进入文章索引、搜索或切换主题。
- 布局：与正文共享窄栏轴线；移动端隐藏次要文字入口，但保留搜索和主题控制。
- 状态：浅色、深色、键盘焦点和窄屏导航。

### 首页 `/`

- 目的：介绍作者关注领域，并让读者进入重点文章。
- 主要动作：打开置顶或近期文章。
- 布局：作者短介绍、置顶手记、近期文章、少量现场注记和完整归档入口。
- 状态：正常内容；文章数据为空不是当前数据模型的有效状态，不新增占位状态。

### 文章索引 `/posts`

- 目的：按年份快速浏览全部文章。
- 主要动作：选择文章。
- 布局：年度标题与紧凑文章清单，不再使用装饰性时间轴。
- 状态：正常列表和现有空状态；空状态仅保留一个返回首页动作。

### 文章正文

- 目的：完成中文技术长文阅读并定位章节。
- 主要动作：阅读正文、使用目录跳转、打开外部资料。
- 布局：约 680px 正文列；桌面目录作为辅助区域，移动端隐藏；文章头部显示分类、日期、阅读时间与可选修订信息。
- 状态：明暗主题下的正文、代码、引用、表格、图片、链接、焦点和移动端溢出。

### 关于、隐私、搜索和错误页面

- 关于与隐私页继承统一正文排版，不重新设计内容结构。
- 搜索弹窗保留现有原生 `dialog` 与 Pagefind 行为，只调整表面、焦点、输入、空结果和错误视觉。
- 错误页保留现有恢复动作，只同步新的主题和排版系统。

不新增路由、弹窗类型、文章数据字段、搜索行为或发布功能。

## 视觉系统

### 色彩

使用语义变量管理主题，组件不得散落主题相关硬编码颜色。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面 | `#fdfdfc` | `#15191b` |
| 主要文字 | `#252a2d` | `#e7eaeb` |
| 次要文字 | `#687076` | `#9ca5a9` |
| 分隔线 | `#dfe2e3` | `#30373a` |
| 强调色 | `#0f766e` | `#5eead4` |
| 代码表面 | `#f2f3f3` | `#202629` |

每个视图只使用一个强调色。深度策略为表面色差与低对比边线，不使用投影建立层级。

### 字体

- 标题、正文和 UI：跨平台系统无衬线字体栈。
- 日期、阅读时间、标签、代码和注记编号：系统等宽字体栈。
- 楷体仅允许出现在极少量作者短批注中，不用于主要信息或长段文本。
- 正文基准 16px，行高约 1.8；通过字重、颜色和间距建立层级。
- 标题使用平衡换行，正文使用优化换行；不增加装饰性字距。

### 布局和密度

- 全站主轴最大宽度约 720px，文章正文约 680px。
- 4px 为基础间距单位，区块间使用不均匀节奏区分阅读组群。
- 首页焦点顺序：作者与站点主张、置顶手记、近期文章、归档入口。
- 不使用重复卡片。文章条目通过日期列、标题字重、摘要和低对比分隔线组织。
- 响应范围覆盖桌面、平板和 390px 手机；输入方式覆盖鼠标、触摸和键盘。

### 视觉签名

“现场注记”至少在以下位置形成一致语言：

1. 首页作者主张下的一句判断。
2. 首页或归档中的 `NOTE / n` 编号。
3. 文章头部的修订或验证状态。
4. 文章元信息中的领域标签。
5. 页脚的持续修订语句。

每一处都应包含可解释的信息。若没有真实内容，则不渲染该元素。

## 明暗模式

主题遵循三态规则：

1. 无本地选择时跟随 `prefers-color-scheme`。
2. 用户切换后将 `light` 或 `dark` 保存到本地。
3. 后续访问优先采用保存值。

在首次绘制前设置根元素主题，避免页面加载闪烁。主题按钮使用原生 `button`，具有可读的 `aria-label`、可见焦点和至少 44px 命中区域。主题切换不增加动画依赖；只允许短时颜色反馈，并尊重减少动态效果设置。

Shiki 代码 token、内联代码、搜索弹窗、引用、目录、表格、图片边线和错误状态必须分别验证两种主题，不能依赖页面整体反色。

## 技术边界

- 继续使用 Next.js 16.0.7、Nextra 4.6.1、React 19.1.0 和 Tailwind CSS 4.3.3。
- 复用现有 `SiteShell`、`Search`、`Article`、错误状态和原生 HTML 控件。
- 不新增 UI 库、主题库、字体 CDN、图标包或动画依赖。
- 不修改文章内容、SEO 元数据、Pagefind、sitemap、canonical 或静态导出流程。
- 主题初始化是唯一需要新增的客户端状态；文章与页面结构继续保持服务端渲染。

## 可行性与风险

结论：可行。

现有 Tailwind 主题变量与全局 CSS 足以建立双主题；站点交互范围小，不需要引入状态库。主要技术风险如下：

- 首次加载主题闪烁：通过绘制前的最小初始化脚本规避，并检查 hydration 警告。
- 深色代码高亮对比不足：分别映射 Shiki 明暗 token，检查代表性代码块。
- 遗留硬编码颜色造成局部失配：审计共享组件和 typography utilities，迁移为语义变量。
- 窄屏文章表格和长外链溢出：在本次代表文章移动端视觉验证中纳入检查，但不借机改写文章内容。
- 过度模仿参考站：保留本站信息结构、中文排版与现场注记，不复制名称、文案或独有组件。

## 验收标准

- 首页不再呈现当前的米白衬线报刊模板。
- 首页、文章索引、文章正文、搜索、关于、隐私和错误页面共享一致视觉系统。
- 首次访问跟随系统主题，手动选择可持久化，刷新无明显主题闪烁或 hydration 错误。
- 明暗主题中的正文、代码、引用、表格、链接、焦点、搜索状态均达到清晰可读水平。
- 390px 视口无页面级横向溢出，交互目标适合触摸操作。
- 键盘焦点清晰，主题切换和搜索可通过键盘完成。
- 不新增生产依赖，不破坏 SEO、搜索或静态导出。
- `pnpm typecheck`、`pnpm check`、`pnpm build` 和必需静态产物检查通过。
- 首页、索引、代表文章和搜索完成桌面/390px、浅色/深色组合视觉检查。

## 验证策略

- 迭代阶段运行受影响文件的 Biome 检查与 TypeScript 类型检查。
- 完成后运行 `pnpm check`、`pnpm typecheck` 和 `pnpm build`。
- 确认 `out/index.html`、`out/_pagefind/pagefind.js`、`out/sitemap.xml` 和 `out/robots.txt` 存在。
- 在桌面和 390px 视口检查首页、索引、代表文章、搜索与错误页的两种主题。
- 检查无 JavaScript、主题保存值以及系统主题三种初始化路径。

## 明确不做

- 不新增文章、分类筛选、阅读进度、评论、订阅或后台功能。
- 不引入远程字体、插图、纹理、渐变或页面入场动画。
- 不重构内容数据层、搜索引擎、SEO 配置或部署流程。
- 不照搬 AstroPaper 的品牌、文案或代码实现。
