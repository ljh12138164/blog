# 文章索引页

## Background

首页承担品牌介绍、最新文章推荐和入门阅读路径，但完整专题归档层级较低，且现有 `lib/posts.ts` 只维护近期文章和部分归档入口。读者缺少一个可以连续浏览全部文章的独立页面。

用户确认新增 `/posts` 文章索引页，并允许把本次安装的 `frontend-design` 技能、技能锁文件和 UI Skills MCP 项目配置一并提交。

## Scope

- 新增 `/posts` 静态文章索引页，覆盖全部文章并按日期倒序组织。
- 每条文章展示日期、分类、标题、摘要和阅读时间。
- 桌面端使用年份索引轨道与文章流水列表，移动端调整为单列。
- 将全站导航“文章”入口改为 `/posts`。
- 建立一份完整且可复用的文章索引数据，避免列表页遗漏文章。
- 提交 `frontend-design` 项目技能、技能锁文件与 UI Skills MCP 项目配置。
- 优化 `develop-with-pr` 的 UI Skills 配置发现与当前会话回退流程。

## Out of scope

- 不增加筛选器、分页、收藏、排序控件或新的搜索实现。
- 不新增 UI 组件库、图标库、图片资产、渐变、阴影或动画。
- 不修改文章正文、文章 URL 或部署配置。
- 不实现暗色模式；站点当前只声明浅色主题。

## Acceptance criteria

- `/posts` 可以从桌面和移动端主导航到达，并可返回首页或进入任意文章。
- 页面列出 `app/posts` 下全部文章，顺序为日期倒序，数量与源文章一致。
- 桌面端年份轨道清晰表达时间结构；窄屏不横向溢出且文章信息自然换行。
- 标题、摘要、日期、分类和阅读时间均来自文章的公开元数据，不维护互相漂移的重复展示文案。
- 链接具有可见 hover 与键盘 focus 状态；日期使用 tabular numbers。
- UI Skills MCP 可由项目级 `.mcp.json` 发现；`develop-with-pr` 记录缺失配置时的添加与当前会话回退方法。
- `pnpm check`、`pnpm typecheck`、`pnpm build` 和必需静态产物检查通过。
- `/posts` 在桌面和移动端完成视觉检查。

## Feasibility

结论：可行。

站点使用 Next.js 16.0.7、Nextra 4.6.1、React 19.1.0 与 Tailwind CSS 4.3.3。页面可保持为静态 Server Component，不需要客户端状态或新依赖。主要技术难点是文章元数据当前分散在 36 个 MDX 文件中，而 `lib/posts.ts` 只覆盖部分文章；实现必须确保列表数量与 MDX 目录一致，并在构建时验证，避免新增文章后索引静默缺失。

UI Skills MCP `https://www.ui-skills.com/mcp` 已通过 MCP `initialize` 与 `tools/list` 验证，服务版本为 0.2.4，提供 `list_skills` 和 `get_skill`。本轮通过协议完整读取了 `dammyjay93/interface-design` 与 `ibelick/baseline-ui`，并新增项目级 `.mcp.json`，后续客户端可能需要重新加载并批准该服务器。

## Implementation

### 已确认界面合同

- 实际读者：希望按主题和时间发现工程实践文章的中文开发者。
- 主要动作：扫描完整文章目录并进入一篇文章。
- 页面焦点：文章标题流水列表；年份和元信息只承担导航结构。
- 视觉感受：像持续更新的工程工作日志，安静、严谨、可快速扫描。
- 颜色：沿用纸张 `#f5f4ee`、墨色 `#18201d`、次级文字 `#64706a`、石墨线 `#d9ddd8`、陶土批注 `#b94f2a`。
- 字体：标题使用现有中文衬线栈；正文和 UI 使用现有系统无衬线栈；日期使用 tabular numbers。
- 深度：只使用现有边线和留白，不引入卡片表面、阴影或圆角系统。
- 间距：以 4px 为基础单位，列表采用中等密度，年份组之间保留明显段落节奏。

### 领域探索与视觉取舍

- Domain：工程日志、日期索引、专题档案、阅读路径、版本沉淀、边注。
- Color world：纸张、墨水、铅笔灰、代码纸、陶土色批注。
- Signature：年份索引轨道贯穿文章条目，让时间结构成为页面骨架。
- Rejecting：卡片网格改为连续日志；大数字统计 Hero 改为标题与索引说明；筛选胶囊改为原生文档搜索与年份锚点。

### 页面结构

- 新增完整页面 `/posts`：标题区、年份概览、按年份分组的文章列表、空数据返回首页入口。
- 修改全局 `SiteShell`：导航“文章”由首页锚点改为 `/posts`。
- 首页内容层级和现有 `/about`、文章详情页保持不变。

## Verification

- `pnpm check`：通过，Biome 检查 32 个文件，无问题。
- `pnpm typecheck`：通过，无 TypeScript 错误。
- `pnpm build`：通过，生成 43 个静态页面；Pagefind 收录 38 页；SEO 校验通过。
- 静态产物：`out/posts.html`、`out/_pagefind/pagefind.js`、`out/sitemap.xml`、`out/robots.txt` 均存在，sitemap 包含 `/posts`。
- 数据完整性：源目录包含 36 篇文章，构建后的索引包含 36 个唯一文章链接；页面按日期倒序并分为 2026、2025、2024 三组。
- 视觉检查：1440px、768px 与 390px 三档均完成；文章数和年份一致，无横向溢出，长标题自然换行，移动端主导航保留“文章”入口。
- UI Skills MCP：`initialize`、`tools/list` 与 `get_skill` 协议调用通过，服务版本为 0.2.4；`.mcp.json` 可被 JSON 解析。

## Review

### Standards

- 符合仓库的静态构建、元数据与 SEO 约定；文章展示数据直接读取 Nextra page map，没有新增重复维护清单。
- 视觉实现沿用现有 token、字体和边线语言，没有引入组件库、图片、渐变、阴影或动画；交互元素保留 hover、全局 focus-visible 与足够触控高度。
- UI Skills MCP 配置仅作用于项目，并以合并而非覆盖其他服务器为明确规则。

### Spec

- `/posts`、全站导航入口、完整文章字段、年份分组、日期倒序与三档响应式布局均满足已确认方案。
- 阻塞发现：初版移动端隐藏了“文章”导航，与“桌面和移动端均可到达”冲突；已修复并重新完成视觉检查。
- 接受的后续工作：无，因此不建立路线图。

## Risks

- 若文章索引与 MDX 元数据采用两套人工维护数据，会发生数量和文案漂移；必须复用或验证元数据来源。
- 年份轨道在长标题和窄屏下可能造成内容列过窄，需要覆盖 390px、768px 和桌面视口。
- `.mcp.json` 是项目共享配置，首次加载时客户端可能提示用户批准远程 MCP。
