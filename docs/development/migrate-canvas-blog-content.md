# 迁移旧博客内容

## Background

独立博客已经具备自定义 Nextra 阅读界面和近期 AI 文章。旧的 `canvas/apps/blog` 保存了博客原始标题文案、32 篇历史文章及配图，需要迁入这里；canvas 项目本身不再作为交付目标。

## Scope

- 迁移 32 篇历史 MDX 文章及其本地图片，并保留原有中文 URL。
- 首页分为“近期文章”和“历史文章”，历史文章按原主题归组。
- 站点名称、首页介绍、关于页主要采用旧博客文案。
- 保持当前纸张色、衬线标题和单一橙色强调的视觉语言。
- 将深黑代码块改成适合当前浅色阅读界面的语法高亮代码块，并保留复制能力。

## Out of scope

- 不修改或继续维护 canvas 应用。
- 不重写历史文章观点、示例或措辞。
- 不部署生产环境，不合并 Pull Request。
- 不增加新的 UI 依赖或页面类型。

## Acceptance criteria

- 3 篇近期文章和 32 篇历史文章在首页分组展示，所有链接均可静态导出。
- 历史文章图片路径有效，文章头不出现重复标题。
- 站点使用“ljh的技术博客”和旧博客的欢迎、作者及联系方式文案。
- 围栏代码具有浅色背景、可辨识的语法颜色、语言标签、横向溢出和可访问的复制反馈。
- 桌面与移动端无页面级横向溢出，搜索可找到迁移文章。
- 类型检查、生产构建以及搜索、站点地图和 robots 产物验证通过。

## Feasibility

结论：可行。当前项目和旧博客都使用 Nextra 4/MDX，正文可直接复用。迁移时将旧的 `index.mdx`/独立 MDX 映射为 App Router `page.mdx`，目录和图片保持相对关系即可保留 URL 与资源引用。

主要技术难点：旧文章路径包含中文并有两种入口文件名；通过显式路径清单和构建出的静态路由验证规避漏页。旧正文部分以 H1 开头；迁移时仅移除与元数据重复的首个 H1。代码示例中可能包含看似 MDX import/JSX 的文本；保留原围栏并以完整构建校验解析兼容性。

## Implementation

UI 交付面仅修改现有首页、文章页、关于页和搜索结果，不新增路由类型。面向阅读技术笔记的开发者，主要动作是按主题找到文章并连续阅读，整体应像克制的纸质技术笔记。

- Intent：技术读者查找和阅读个人实践记录；安静、温暖、可信。
- Hierarchy：首页标题和文章标题为焦点，以字号、字重与留白建立层级。
- Palette：沿用纸张白、墨色、灰绿分隔线和橙色强调。
- Depth：沿用低对比边线，不增加装饰阴影或渐变。
- Typography：沿用衬线标题/正文与无衬线导航、元数据。
- Spacing：沿用现有 4px 倍数和宽松阅读密度。

已加载 UI Skills `dammyjay93/interface-design` 与 `ibelick/baseline-ui`。用户已明确确认保持当前风格；因此复用现有视觉决策、Tailwind 4.3.3、Nextra 4.6.1 和原生交互，不引入组件库。

历史文章按原目录映射到 App Router，并根据 canvas 仓库的首次提交日期补齐日期；阅读时长按正文规模生成。迁移只移除正文开头与文章头重复的一级标题。静态导出启用 `images.unoptimized`，让 Nextra 的本地图片直接引用构建资源，避免依赖不存在的运行时图片优化接口。

代码块通过 MDX `pre` 覆盖统一渲染，沿用 Nextra/Shiki 的 token 颜色，外层提供语言标签、横向滚动和复制成功/失败反馈。搜索切换为原生 `dialog`，处理查询竞态并把 Pagefind 的 `.html` 地址还原为站内路由。

后续内容调整按用户要求删除《RAG 不是魔法》，并使用 `/teach` 的教学设计原则重写《如何为 AI 应用设计高质量提示词》和《Token 与 Context：模型究竟看见了什么？》。两篇文章均使用“学习目标—心智模型—示例—主动回忆—练习—权威来源”的结构，同时保留现有 Nextra 文章路由和视觉样式。

- 完成标准与范围评审：没有阻塞项，也没有需要另建 roadmap 的已接受后续项。

## Risks

- 中文静态路径依赖文件系统和导出编码，必须以最终 `out` 产物验证。
- 历史文中的外部链接与过时技术结论按原文迁移，不在本次范围内校订。
