# 404 与错误页面视觉优化

## Background

当前项目没有自定义 App Router 错误页面，未知路由会落入 Next.js 默认的黑色 404 区块，和博客的纸张、墨色与陶红视觉体系明显割裂。

## Scope

- 新增站点级 `not-found.tsx`，为未知路由提供清晰的返回入口。
- 新增客户端 `error.tsx`，为可恢复运行时错误提供重试与返回首页操作。
- 复用一个错误状态呈现组件，使两类页面保持一致的视觉、语义与响应式行为。

## Out of scope

- 不修改正常文章、首页、页头、页脚或搜索交互。
- 不新增 UI、图标或动画依赖。
- 不处理绕过根布局的 `global-error.tsx`；当前需求对应站点内容区内的 404 与可恢复错误边界。

## Acceptance criteria

- 404 与 error 页面使用现有纸张色、墨色、弱化色、线框和陶红强调色。
- 404 显示明确的“页面不存在”说明，并提供返回首页和浏览文章入口。
- error 显示明确的“页面暂时无法显示”说明，并提供重试和返回首页入口。
- 页面在桌面与移动端均无横向溢出，键盘焦点清晰，并尊重 reduced-motion 设置。
- `pnpm typecheck` 与 `pnpm build` 通过；构建产物验证确认静态 404 已替换默认页面。

## Feasibility

结论：可行。Next.js App Router 16 原生提供 `not-found.tsx` 和客户端 `error.tsx`，现有静态导出流程会生成 `out/404.html`，无需新依赖。

主要约束是 `error.tsx` 必须为 Client Component 才能调用 `reset()`；共享呈现组件因此保持为客户端组件。静态导出的 404 继续由根布局的 `SiteShell` 包裹，以保留现有导航和页脚。

## Implementation

- 交付面仅包含 `/404` 对应的未知路由状态，以及 App Router 可恢复错误边界。
- 受众是误入失效链接或遇到页面运行错误的博客读者；首要动作分别是返回有效内容和重试当前页面。
- 沿用 `paper #f5f4ee`、`ink #18201d`、`muted #64706a`、`line #d9ddd8`、`accent #b94f2a`。
- 标题继续使用项目 serif 字体，正文与操作使用 sans 字体；不引入新字体。
- 页面使用现有 1120px 内容宽度和 8px 间距节奏。桌面为状态码与说明双栏，移动端折为单栏。
- 唯一视觉特征是一条请求诊断轨迹；其余区域保持克制，不使用卡片、渐变、阴影或无意义动画。

## Risks

- `error.tsx` 只有在运行时边界触发时出现，静态导出不能直接生成该状态；通过类型检查、生产构建和共享组件的一致性降低风险。
- GitHub HTTPS 当前连接超时，可能阻塞分支推送和 PR 创建，但不影响本地实现与验证。
- 用户明确要求跳过自动化测试；本任务以类型检查、生产构建和渲染检查验证。
