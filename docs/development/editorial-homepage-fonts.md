# 编辑型首页与字体体系

## Background

当前站点以纸张底色和衬线排版形成编辑感，但文章正文整篇使用衬线字体，中文、英文和数字会因操作系统字体回退产生不稳定的混排效果。桌面首页 Hero 高度较大，首屏难以发现文章内容。

用户已确认采用评审中的推荐字体方案与首页方案 A：标题保留衬线气质，正文和 UI 使用无衬线；首页缩短 Hero，并以最新文章主推荐和 3 篇“从这里开始”提升内容发现效率。

## Scope

- 调整全局字体回退链，正文和 UI 使用跨平台系统无衬线字体。
- 文章标题和章节标题继续使用衬线字体，文章正文改用无衬线字体。
- 优化文章移动端标题尺寸与正文可读性。
- 将首页第一篇近期文章提升为 Hero 内的主推荐。
- 将其余 3 篇近期文章展示为“从这里开始”。
- 降低完整专题归档的视觉权重，同时保留全部入口。
- 覆盖桌面端和移动端响应式布局。

## Out of scope

- 不增加新的页面、路由、图片资产、动画或 UI 依赖。
- 不引入外部字体 CDN，也不下载完整中文 Web Font。
- 不修改文章目录数据、文章正文、搜索行为或发布配置。
- 移动端既有横向溢出问题另行诊断，不在本次首页与字体改造范围内。

## Acceptance criteria

- 品牌、首页大标题和文章标题保留衬线字体；导航、正文、元信息和文章内容使用无衬线字体。
- 字体回退链不依赖未加载的 `Inter`，并在 Windows、macOS 和常见 Linux 中文环境下有明确回退。
- 桌面首页 Hero 明显缩短，并在 Hero 中显示最新文章主推荐。
- 首页主推荐之外恰好展示 3 篇“从这里开始”文章。
- 完整专题归档仍可访问，但标题尺寸、间距和文字层级低于主推荐与起始文章。
- 搜索、焦点样式、语义标题层级和移动端单列布局保持可用。
- `pnpm typecheck`、`pnpm build` 与必需静态产物检查通过。
- 桌面和移动端的首页及代表性文章完成视觉检查。

## Feasibility

结论：可行。

现有首页数据已将 4 篇近期文章集中在 `lib/posts.ts`，可直接通过数组解构形成 1 篇主推荐与 3 篇起始文章，不需要迁移数据。Tailwind CSS 4 的主题字体变量和现有响应式工具足以完成改造，不需要新增组件库。

主要技术约束是中文 Web Font 体积大，且站点已有中国内地访问优化目标。因此本次采用系统字体栈，不引入网络字体；代价是不同操作系统字形不会完全一致，但正文类别、字重和混排稳定性会明显优于当前整篇衬线方案。视觉验证必须覆盖 Windows Chrome 的桌面与 390px 移动视口。

UI Skills MCP 注册表在当前任务中未暴露工具或资源，无法加载 `dammyjay93/interface-design` 与 `ibelick/baseline-ui`。本次回退到仓库的 UI quality 规则和既有设计系统，不声明 UI Skills MCP 合规。

## Implementation

- 界面对象：技术博客读者；主要动作是进入重点文章。
- 焦点层级：最新主文章 > 3 篇起始文章 > 专题归档。
- 视觉方向：保留纸张底色、墨色和陶土橙单一强调色；不增加阴影、渐变或新的圆角卡片体系。
- 字体层级：品牌与标题为衬线，正文和 UI 为无衬线，代码为等宽。
- 密度：Hero 从展示型大留白调整为中等密度；归档更加紧凑。
- 技术栈：Next.js 16.0.7、Nextra 4.6.1、Tailwind CSS 4.3.3；复用 `Link`、`SiteShell`、现有颜色和字体 token。
- 路由范围：仅修改现有 `/` 首页和所有文章共用的 `Article` 排版；无新增路由或交互状态。
- 首页直接解构 `recentPosts`：第一篇为 Hero 主推荐，其余三篇为“从这里开始”，避免引入重复的精选文章配置。
- 文章容器移除整篇 `font-serif`，仅通过 `prose-headings:font-serif` 保留章节标题的衬线气质；摘要、正文、列表、搜索摘要和页脚统一继承无衬线字体。
- 移动端文章 H1 调整为 38px；正文段落行高为 1.85，列表行高为 1.8。
- 首页无新增卡片表面、阴影或动画，继续用边线、留白和字体层级区分内容。

- UI Skills MCP 注册表不可用，因此以上视觉验证依据仓库 UI quality 规则完成，不声明 UI Skills MCP 评审通过。

## Risks

- 系统字体栈只能稳定字体类别与回退顺序，无法让所有系统像素级一致。
- 首页对 `recentPosts` 的顺序有语义依赖：第一项必须始终是最新主推荐。
- 缩短 Hero 后需要检查长标题在窄屏上的换行与推荐区高度。
- 代表文章在 390px 下仍有既有表格横向溢出：文档宽 375px、表格右边界 449px。该问题不由本次字体改造造成，作为评审后的候选跟进项分类。
