## Token 是什么

Token 是模型读取和生成文本时使用的基本单位。它不一定等于一个字，也不一定等于一个完整单词。分词器会把文本拆成模型词表中已有的片段，再把每个片段转换成数字编号。

例如，“我喜欢人工智能”可能被拆成若干汉字或词组；英文 `unbelievable` 也可能被拆成 `un`、`believ`、`able`。具体结果取决于模型使用的分词器。

> Token 是计量单位，不是模型真正理解世界的最小概念。

## Context 是什么

Context（上下文）是模型在生成当前回答时能够参考的信息。它通常包括系统指令、之前的对话、用户本次输入、工具返回结果，以及模型已经生成的内容。

模型不会像人一样自动记住所有历史。只有被放进当前上下文的信息，才有机会影响下一步输出。

## 上下文窗口

上下文窗口是一次推理可容纳的 Token 总量。输入和输出通常共享这个额度：输入越长，可生成的空间就越少。

窗口更大并不代表模型能同等准确地利用其中每一条信息。重要内容被大量无关材料包围时，仍可能被忽略。因此，整理上下文往往比单纯增加上下文更有效。

## 注意力在做什么

注意力机制帮助模型在生成每个 Token 时，为上下文中的不同位置分配不同权重。它使模型能够关联远处的词语，但不是一个可以无限容量、精确检索的数据库。

## 三个常见误区

1. **一个汉字就是一个 Token。** 实际数量取决于分词器。
2. **对话越长，模型了解得越多。** 噪声也会随之增加，旧内容还可能被截断。
3. **上下文等于长期记忆。** 上下文是本次推理的工作区；长期记忆需要外部存储和重新检索。

## 实践建议

提供明确目标、必要背景、约束条件和期望格式。长文档先筛选相关片段，再交给模型。重要要求放在清晰、容易定位的位置，并让模型复述关键约束以便检查。
